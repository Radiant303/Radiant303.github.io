# 这个页面的液态玻璃是怎么实现的

这个页面顶部的导航滑块，是一块真的会折射背景的「液态玻璃」。它没有用任何框架，核心是一个 SVG 滤镜，和一张用 Canvas 逐像素算出来的位移图。思路来自 shuding 的 [svg-shaders](https://github.com/shuding/svg-shaders) 与 [liquid-glass](https://github.com/shuding/liquid-glass)（MIT），这里记录我实现时真正踩过的坑。

## 原理：feDisplacementMap

SVG 的 `feDisplacementMap` 滤镜可以根据一张图的 R/G 通道，把输入图像的每个像素「挪」到别的位置。所以只要算出「每个像素应该从哪里采样」，把偏移量编码进一张图的红色和绿色通道，浏览器就会替我们完成折射。

位移图由 Canvas 逐像素生成：对一个圆角矩形 SDF 求距离，在边缘的过渡带内，让采样点沿法线方向向内收一个固定的像素距离——这就是玻璃边缘那圈「拉伸」的来源。通道以 0.5 为中心编码正负偏移，滤镜的 `scale` 设为最大偏移的两倍，把归一化值还原成像素位移。

```js
// 边缘拉力：过渡带内沿法线内收 rim 个像素
var s = smoothStep(0, -bezel, d);      // 边缘 0 → 深处 1
var pull = rim * (1 - s) * (1 - s);    // 越靠边缘拉得越狠
```

## 坑一：Chrome 不会替你裁圆角

`backdrop-filter: url(#filter)` 在 Chrome 里的滤镜区域是一个矩形，它不会跟随元素的 `border-radius` 裁切。结果就是：圆角之外会露出一圈被扭曲的背景，非常难看。

解决办法是把裁切做进滤镜内部：再生成一张圆角矩形的蒙版图，用 `feComposite operator="in"` 把位移后的结果和蒙版求交，只保留圆角矩形以内的部分。

蒙版还要向外多画 2px——否则 `feComposite` 会在边框内侧留下一圈没有被折射的细缝。那是元素边缘的抗锯齿像素没被盖住导致的，放大截图才能看到，但看到之后就再也回不去了。

## 坑二：位移量要用像素，不能用比例

最初的版本按元素尺寸的百分比计算边缘拉力，结果大块玻璃的边缘出现了「重影」：拉力随尺寸放大，位移图超出了预期范围。改成以像素为单位之后，无论玻璃多大，边缘的折射强度都是恒定的——视觉上才像「同一块材料」。

## 坑三：滤镜引用要等一帧

滤镜节点必须先插入 DOM，下一帧再设置 `backdrop-filter: url(#id)`，否则 Chrome 偶发不渲染。另外 `backdrop-filter` 里只挂 `url()`，不再串 `blur()` 或 `brightness()`——那些函数会作用在矩形的滤镜区域上，圆角处又会露馅。

## 为什么不给所有元素都用上

因为克制。液态玻璃在全站只出现在两个地方：首页的导航滑块，和文章页的返回按钮。它折射底下的文字，提醒你它的存在，然后让开。正文直接印在素白的纸面上——阅读的地方，稳定比炫技重要。
